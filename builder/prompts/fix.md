A phone agent was compiled from `spec.json` (a policy spec read from the brief) and tested in simulated calls. $n_fail of $n_total test calls failed. `failures.json` lists each failed call: what the test expected, what went wrong, the tools the agent called, and the end of the transcript.

## Files

The brief: $briefs. `openapi.json`, `spec_schema.json` and `spec-guide.md` describe the tools and the spec. When documents conflict, the latest dated decision wins, even unlabelled; a document that only proposes, discusses or forwards decides nothing.

## How to read a failure

The tests are generated by code from `spec.json` itself, so a test can only fail on the spec when the spec is ambiguous, incomplete or contradicts the brief in a way the dialogue exposes. Many failures are the agent's wording or the simulated customer, and the spec cannot fix them. Do not change the spec to make a test pass; change it only where the brief shows the spec is wrong or missing something.

For each failure:
1. Read the transcript and the failure reason.
2. Find the brief text that governs that moment of the call.
3. If `spec.json` disagrees with that text, or leaves out a rule the brief states, write a decision. Otherwise write nothing for it.

## Output

Write `fix.json`:

```
{
  "decisions": [ {"path": "...", "value": <the full JSON value at that path>, "quote": "exact brief words", "why": "one line naming the failed test id"} ]
}
```

- Paths use the spec's syntax: dotted keys, `[index]`, or `[id]` for list items with an id (`events[<id>]`). An `events[<id>]` path takes the whole event object, `outcomes` the whole table. To delete a path, give `"remove": true` instead of `value`.
- Every decision needs a `quote` copied word for word from the brief. A decision without one, or with a quote not found in the brief, is discarded.
- Keep the spec consistent: a changed event needs its matching `outcomes` rows (and the reverse).
- Do not edit `spec.json` or any other file. No change at all is a valid answer: `{"decisions": []}`.

Reply with the single word `done`.
